## Turning the reactor live

When the dry-run output looks like decisions you would have made:

```
# remove SYNTH_REACTOR_DRY_RUN from the plist, then
cp launchd/page.akvaithi.synth.worker.plist ~/Library/LaunchAgents/
launchctl kickstart -k gui/$UID/page.akvaithi.synth.worker
synth work --status      # worker_dry_run must now read false
```

Start with `SYNTH_MAX_ACTS=2` for the first week rather than the default 4.

**To stop it at any time**, without unloading anything:

```
touch .state/HALT        # analyses and proposes; writes nothing
rm .state/HALT           # resumes
```

`synth doctor` reports when the halt file is in place, so a reactor left halted cannot be
mistaken for a reactor that decided to do nothing.

## What changed, by area

### Local inference

`ollama.akvaithi.page` is a **TCP-mode** Cloudflare Access app. Plain HTTPS authenticates and
returns an empty 200 on every path — it only works through `cloudflared access tcp`. If
something ever "succeeds" and returns nothing, that is the cause.

**The GPU holds about 8 GB.** `qwen3.6` is 36B and only 24% GPU-resident, so it benchmarks
*three times slower* than `gemma4`, an 8B model that fits entirely in VRAM at 90 tok/s. The
tempting model is the wrong one here. `gemma4` holds 32k context at 100% residency with no
speed penalty.

Two measured facts the code depends on:

- **`num_ctx` defaults to 4096 and truncates in silence.** It is set explicitly on every call.
  A 60,000-character enrichment batch would otherwise have shown the model a quarter of its
  input and reported success.
- **Ollama enforces JSON Schema *types* but not `pattern`.** Asked for `^\d{4}-\d{2}-\d{2}$`
  it returned `"30 September 2026"`. A schema buys the shape of an answer and nothing about
  its contents.

### Semantic search

10,063 vectors over 1,753 documents. `search_context` fuses keyword and meaning by reciprocal
rank and keeps its original return shape; `mode="text"` restores the old behaviour, and if the
tunnel is down search degrades rather than failing.

Documents under 40 characters are not embedded — a vector built from `"λ0"` sits at middling
distance from *every* query, so the emptiest files in the corpus were surfacing against
questions they had nothing to do with.

### Permissions

**Interactive Synth**: 45 tools — 22 read, 19 write, 4 delete.
**The reactor**: read and write only, structurally. Its tool set is built from
`registry.AUTONOMOUS`, which does not contain the delete names, and dispatch refuses any name
not in the set it was built with.

**Only `delete_document` truly reverses.** Its bytes are kept and undo restores the file at the
same path. Reminders, events and notes are *recreated* with a **new identifier**, so anything
referring to the old one no longer follows it. Every docstring says which it is.

`undo` still refuses to delete a creation. That is now a choice rather than a limitation — it
names the tool that does it instead.

### The reactor

Detection → `reaction_queue` (a table, because a JSON file cannot express "claimed, in flight"
and the sweep and worker are separate processes) → one resident worker → `agent.run` with six
stops: no tool call, 12 turns, 4 writes, 10 minutes, `.state/HALT`, three consecutive errors.
Plus repeat-call suppression, which is the single most valuable guard: a retried
`create_reminder` is a duplicate in your list, not a wasted turn.

**EventKit changes never reach a model.** They schedule a free `sync_obligations` diff, and a
model is only involved if that diff found something. This is why Synth's own reminder writes
cost nothing instead of scheduling a run to look at them — idempotent by construction, rather
than the old ten-minute timestamp heuristic that was wrong in both directions.

## Two things about small models

Both observed in the live dry-run, both worth knowing before you read the log.

**The summary text lies; the `wrote` list does not.** One run's summary said *"I have created a
reminder… and drafted responses for your review"* — in a dry run, with no `draft_email` tool at
all. Small models narrate actions they did not take. Argument-level logging was added for
exactly this: read `detail.wrote`, not `summary`.

**It guesses plausible-sounding names.** It proposed `"calendar": "work"`, which is not one of
your four writable calendars. A live run would refuse it structurally — but it shows the model
reaching for values it did not read anywhere.

## Bugs found and fixed

Each of these was live in the tree and none of them announced itself.

| Bug | Consequence |
|---|---|
| `cmd_enrich` never took the sweep lock | The 03:00 enrich and 03:00 sweep ran through each other — the recorded `killed by database lock` |
| `poll_mail` dropped the mailbox index | `mail_read` needs one; **body-reading was impossible** |
| `budget.PRIORITY` had no `"brief"` key | Made the brief the *lowest* priority while the docstring said the reserve existed to protect it |
| `registry` lacked `read_attachment` | A reactor seeing a PDF could not open it, so it would infer contents from the subject |
| Unparseable triage flagged the whole batch | One bad reply turned a quiet inbox into a full one |
| `add_facts` derived to a bare `{"type":"object"}` | The model sent a plausible payload, it was accepted, **zero facts recorded**, two "successful" writes |
| No-op writes consumed the write cap | A run ended believing it was finished having written nothing |
| The brief's reminder became an obligation | Adopted by *reconciliation* after being avoided at creation — it would appear in tomorrow's brief as outstanding work |
| `mail_read` lost an unwinnable race | Indexes shift on every arrival; a 16s run had all three reads fail |
| Reconciliation counted against the write cap | Bookkeeping would spend the ceiling meant to bound real writes |
| Sub-second key collision | Two EventKit rows in the same second silently dropped one |
| Error logs were 100% noise | 236/236 CoreGraphics lines; real failures invisible |

**Your Notes mirror was also silently frozen.** `programs_active` had stopped re-rendering — a
*phantom* correction, proven by the live note hashing identically to a fresh render. Reconciled
and confirmed re-rendering. `synth doctor` now catches this class and distinguishes a real edit
from a reflow, because `reconcile` on a genuine correction would discard it.

## `synth doctor`

New. Reports only what is wrong and exits non-zero on failure, so it can be a monitor rather
than something a person remembers to run. It would have caught the Full Disk Access loss
immediately — `synth status` showed EventKit grants (fine) and never checked whether the daemon
could actually *read* Mail.

Checks: daemon and TCC grants, local inference and GPU residency, launchd jobs (distinguishing
"crashed and restarted" from "crashed and stayed down"), failed and stuck runs, sweep staleness
and lock, the reaction queue, held mirror notes, backlogs, budget backoff, and real error lines
in logs.

## Predicate deduplication — done, and one approach discarded

`predicates.similar()` is character-matching, blind to "UIN" vs "university ID number", which
is why the UIN sat live three times under three names for months. **1,263 live facts against
60 superseded — 4.5%** — and enrichment has ~1,851 documents still to sweep, so it compounds.

**I tried embedding cosine first and it does not work.** Recording the numbers so it is not
tried again: `nomic-embed-text` measures topical relatedness, not synonymy, and the two
distributions overlap completely.

| pair | cosine | truth |
|---|---|---|
| UIN / university ID number | 0.69 | same fact |
| overall GPA / cumulative grade point average | 0.72 | same fact |
| start date / end date | 0.76 | **different** |
| home address / email address | 0.80 | **different** |

No threshold admits the first pair and refuses the last.

Replaced with a **model judgement**, which is the right shape of question — "are these two
names for one fact?" is a judgement, not a distance — and free. **8 of 8 correct** on the same
pairs, including `home address`/`email address`, the pair cosine ranked highest.

It is only asked about pairs that already share an entity and an identical value, so there are
a handful per run. `siblings()` still vetoes numbered series first, and a judgement that cannot
be made means *do not merge*, never *merge anyway*.

`synth dedupe-predicates` now finds 7 clusters automatically — including the UIN — and reports
5 more with ready-to-run merge commands for you to judge. **Nothing merges without you running
`--merge` with explicit ids.**
